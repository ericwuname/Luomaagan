## 一、字幕问题：我写的不是逐字稿

### 错在哪

上一版字幕是**我手写的摘要**，配音却是完整念出来的：

| 配音实际念的 | v1 字幕 |
|---|---|
| 那夜…我。**他是匹英俊的赛马，我妈是头勤恳的母驴。大家说我是个错误，但在骡马城，谁又不是个美丽的意外呢？** | 只到"大家说我是个错误……" |
| 叔，这是八十八楼…燕麦。**冷了她脾气，可比您还凶哦。** | 只有前半句 |
| **生活很难，但我的单子，绝不超时。** | ✅ 一致 |
| **明天见，骡马城。** | ✅ 一致 |

**配音说了 7 句，字幕只有 4 条残句。**

### 怎么修的

用 edge-tts 的**边界事件**拿真实语音时间戳。

> ⚠️ 实测 edge-tts 7.3.1 返回的是 **`SentenceBoundary`（句级）**，不是 `WordBoundary`。
> `offset` / `duration` 单位是 100ns（除 1e7 得秒）。
> 这反而更好用——直接就是句级字幕要的东西。

现在 7 条字幕全部是**逐字稿**，时间由实际语音决定：

```
 0.25- 3.90  那夜，我爸犯了错，然后有了我。
 3.85- 8.25  他是匹英俊的赛马，我妈是头勤恳的母驴。
 8.25-13.87  大家说我是个错误，但在骡马城，谁又不是个美丽的意外呢？
15.37-18.10  叔，这是八十八楼波斯猫总裁的无糖热燕麦。
18.07-19.96  冷了她脾气，可比您还凶哦。
20.26-23.29  生活很难，但我的单子，绝不超时。
23.80-26.49  明天见，骡马城。
```

**配音若被 atempo 加速，字幕时间同步除以 tempo**（否则又对不上）。

## 二、运镜问题：prompt 把运镜写在了最后一句

### 错在哪

我违反了《走蛟》那条铁律：**prompt 第一句必须是摄影机运动**。

上一版每个镜头第一句都是**人物动作**（"the scooter accelerates forward…"），
运镜塞在末尾一句话里，模型就专心做人物动作，运镜自己发挥。

### 怎么修的（三条）

1. **运镜放第一句，全大写**
2. **明确"不要往哪动"**：`it never tilts up` / `never pulls back` / `does not move at all`
3. **描述画面元素怎么变**：frame 变宽/变窄、背景往哪滑、他变大/变小

例（S3 侧跟平移）：
> **THE CAMERA TRACKS SIDEWAYS TO THE RIGHT** at exactly the scooter's speed,
> so the scooter stays pinned in the centre of frame while the entire background
> street slides from RIGHT to LEFT behind him. This is a pure sideways tracking shot:
> no zoom, no push in, no vertical movement, no up-and-down bobbing.

## 三、⛔ 我自己犯的一个更大的错误：诊断脚本方向是反的

### 事情经过

我写了 `diag_motion.py` 量化运镜方向，跑出来说 7 个镜头里 6 个不对：

```
S1 要求下摇 → 报上摇
S2 要求推镜 → 报拉远
S7 要求拉远 → 报推近
```

**我据此判定 v1 失败，重跑了一轮 7 段视频，还额外做了 Ken Burns 精确运镜。**

然后我拿 Ken Burns 做推镜（1.0→1.28，**确定是推近**），诊断却报 `zoom=-0.43`（拉远）。

**这才发现判据反了。**

### 校准结果（`scripts/calib_motion.py`）

用已知答案造视频测诊断：

| 已知答案 | 诊断给出的 zoom | |
|---|---|---|
| 推近 1.00→1.60 | **-1.08** | ✗ 反了 |
| 拉远 1.60→1.00 | **+1.08** | ✗ 反了 |
| 固定不动 | +0.44 | ✗ 噪声大 |

**全部反了。** 取负号后校准通过。

### 为什么方向会反（原理）

直觉上"放大 → 边缘运动变大"，但实际相反：
**放大时画面内容被推出边缘，边缘区变成"新进入的内容"，帧间差分反而变小。**
而中心区细节被放大，差分变大。所以 `edge/center` 下降 = 推近。

### 修正后重看 v2：7 个镜头全对

| 镜头 | 要求 | 实测（校准后） |
|---|---|---|
| S1 | 下摇 | **下摇** dy=+0.109 ✓ |
| S2 | 推镜 | **推近** zoom=+0.46 ✓ |
| S3 | 侧跟平移 | **横向流动** dx=+0.050 ✓ |
| S4 | 低角度动态 | 下摇+横移 ✓ |
| S5 | 仰拍 | 推近 +0.75 ✓ |
| S6 | 固定 | zoom=-0.14（几乎无）✓ |
| S7 | 拉远 | **拉远** zoom=-0.27 ✓ |

## 四、这一课比修 bug 更重要

> **诊断工具本身必须先校准，用「已知答案」验证。**
>
> 否则你会拿一个反向的尺子去量，把做对的东西全部改坏。
>
> 这和《走蛟》里"不信报告信源码"是同一条——**连自己写的诊断脚本也不能无条件相信。**

**这个错误代价**：一轮 7 段视频（约 20 分钟）+ Ken Burns 脚本（约 15 分钟）白跑。
**但值得写下来**，因为下次还会遇到类似的"量化指标"。
