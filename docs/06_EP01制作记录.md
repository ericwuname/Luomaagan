## 三、踩到的三个坑（都写了修法）

### 3.1 ⛔ `extra_body.image` 要纯 base64，不能带 data URI 前缀

报错：`invalid image base64: illegal base64 data at input byte 1`

原因：传了 `data:image/png;base64,xxxx`，**第一个字符 `d` 不是合法 base64**。
修：只传纯 base64 字符串。

### 3.2 ⛔ 更隐蔽的：路径字符串被当成 base64 直接发了

第一版修复后还报同样的错。查代码：

```python
imgs = [im if isinstance(im, str) else _b64(im) for im in init_images]
```

**传进来的是文件路径字符串，`isinstance(im, str)` 为 True，于是路径被当成 base64 直接发出去。**

修：加 `_prep_images()`，按 `http` / 文件存在 / 其它 三路判断。

> **教训：`isinstance(x, str)` 判断不了"这是路径还是编码数据"。**

### 3.3 ⛔ keyframe 模式的图片字段叫 `first_frame`，不是 `images`

报错：`keyframe 模式需要 first_frame 或 last_frame`

字段对应（实测）：
| mode | 图片字段 |
|---|---|
| `keyframe` | `first_frame`（+ 可选 `last_frame`） |
| `reference` | `images`（列表） |
| `text` | 不带图 |

### 3.4 ⛔ 把 `anullsrc` 放在第 0 个输入，导致第一条配音消失

混音时用 `-f lavfi -i anullsrc` 做静音底，它占了**输入索引 0**。
但 filter 里 `[0:a]` 指向的正是这个静音源，**第一条配音（旁白）被应用到了静音上**。

**症状：成片开头 3.5 秒完全静音（-41dB）。**

修：真实输入的索引从 **1** 开始。

### 3.5 ⛔ 长旁白不能硬塞进短镜头

L00 旁白 **13.78 秒**，但我原来给它分配的是 3.4 秒的 S1 镜头。
`atempo` 最多压到 1.6 倍，压不到 3.4 秒。

修：**配音改成按"秒"铺，不按镜头铺**。
旁白从 0.3 秒开始，横跨 S1–S4，字幕按句切分。

### 3.6 ⛔ 环境底太轻，人声停顿会掉到 -51dB

`anoisesrc a=0.030 + volume=0.45` → 停顿处 -51dB，听感"声音断了"。
修：`a=0.10 + volume=0.85` → 停顿约 **-33dB**，是"安静但没死"的区间。
