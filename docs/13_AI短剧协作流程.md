# 《骡马阿甘》AI 短剧协作流程 V1

> 目标：解决“故事写出来了，但画面要脑补、镜头不连、笑点不响、声音与剪辑返工”的系统性问题。
> 本文是建议流程，不替代主创对故事和成片的最终决定。
> 原则：先把不确定性前置到文档和静帧阶段，不把贵的生成配额花在尚未通过叙事审查的镜头上。

## 1. 重新定义交付物：不只交“故事”或“分镜”

每一集最终需要一份完整的导演包，包含：

1. **故事核心页**：一句话故事、主角目标、主要障碍、转折、结尾、笑点清单。
2. **剧本**：按场景写清楚谁想要什么、障碍是什么、人物怎么改变；对白短，不能替画面重复解释。
3. **导演分镜表**：每镜景别、摄影机运动、人物位置与朝向、单一动作、台词/音效、时长、与上一镜和下一镜的匹配关系。
4. **视觉连续性圣经**：角色参考图、服装、道具、场景布局、屏幕方向、光线时段、已锁定资产。
5. **生成包**：共享的角色与风格前缀、每镜首帧提示、视频运动提示、参考图使用规则、后期合成文字清单。
6. **声音包**：逐字台词、情绪与语速、每条语音实测时长、环境音、音效与 BGM 分轨表。
7. **剪辑决策表**：每镜入点/出点、切点理由、节奏曲线、J-cut/L-cut（如有）、笑点后的反应时间、音乐转折。
8. **验收表**：叙事是否看懂、笑点是否成立、画面是否匹配、音频是否有异常、技术文件是否可重现。

## 2. 每个 AI / 人类角色应做什么

### 主创 / 用户
- 唯一的最终审美和内容决策人。
- 只需要判断：故事值不值得讲、人物是不是这个人物、笑点有没有作用、成片愿不愿意发布。
- 不应该被迫同时承担所有技术细节的专业判断。

### ChatGPT（编剧顾问 + 导演台）
- 负责故事结构、因果链、笑点设计、分镜逻辑、画面动作的可视化、镜头连续性、剪辑节奏、配音与音效计划。
- 在剧本定稿前主动做“观众理解测试”：不读说明的人只看镜头，能否知道发生了什么？
- 不直接宣布 AI 生成效果合格；必须依据首帧、源视频、音轨与量化验收结果判断。

### Gemini / Claude / 其他模型（按需作为独立评审或执行者）
- 以单一任务加入：例如独立指出故事理解断点、评审首帧构图、检查角色一致性或审查镜头运动提示。
- 不允许两个模型同时直接改同一份主剧本。不同意见写成单独方案或分支，通过评审后再合并。

### 本地 Python / FFmpeg 工具链
- 负责可重复的机械任务：图片和视频生成任务管理、片段归一化、逐字字幕时间、帧数与冻结帧检查、音频峰值检查、分轨混音和最终合成。
- 量化工具必须先使用已知答案样例校准；不能把未校准的自动评分当成事实。

## 3. 八道生产闸门

### Gate 0 — 约束与状态确认
确认角色定妆参考、风格、画幅、目标时长、镜头预算、可用素材与视频配额。README、AGENTS、当前剧本、成片状态必须一致；过期的状态文本先标为历史，不得继续误导代理。

**通过条件：** 每个人读到的是同一套当前设定；不确定的角色/美术项明确标为“暂定”。

### Gate 1 — 故事审查（还不生成图）
检查：
- 3 秒内观众知道主角是谁、现在发生什么吗？
- 主角此刻想要什么？
- 什么事情阻挡他？
- 每个笑点是否有“铺垫 → 动作/反转 → 反应”的可见链条？
- 结尾是否回收开头道具、目标或动作？
- 是否有任何信息必须靠作者说明才能理解？

**通过条件：** 先用文字讲给一个没看过项目的人听，对方能复述因果。没有通过就只改故事，不开生图。

### Gate 2 — 导演分镜审查（还不生成视频）
核对每镜的唯一任务、景别、画面布局、人物位置、视线方向、摄影机运动、动作起终点、声音与切点。所有进入/离开画面的方向必须明确，所有对话都要有对应反应镜头或动作承接。

**通过条件：** 分镜表能说清楚“画面里具体发生什么”，而不是只写“他感到孤独/很开心”。

### Gate 3 — 首帧 contact sheet 审查
只生成静帧，不立即生成视频。按顺序拼成 contact sheet，检查：
- 主角是否一致，配角是否都是动物；
- 空镜中是否错误出现主角；
- 道具、衣物、房间布局是否连续；
- 视线、朝向和镜头轴线能否接上；
- 画面是否足以讲清楚动作和笑点；
- 构图是否支持计划中的摄影机运动。

**通过条件：** 人工确认关键首帧。首帧未过，禁止花配额生成视频。

### Gate 4 — 低成本动态测试
只挑 1–3 个最高风险镜头做视频：主角大动作、多人同框、门内外切换、镜子、道具交接等。先测试生成稳定性与运动方向。

**通过条件：** 关键动作真实发生，运动方向与预期一致，角色与道具没有严重漂移。失败 3 次就换镜头设计，不在同一个坏构图上无限抽卡。

### Gate 5 — 批量生成源片
严格按通过的首帧与运动提示串行生成。每个素材都保存 prompt 原文、参考图、模型/参数、目标时长、实际时长、生成结果和失败原因。不可只用“文件存在”判断生成成功；下载后须完整解码验收。

### Gate 6 — 声音与粗剪
对白单独生成并测实际时长；先排对白与反应，再安排镜头长度。AMB、EVT、MUS、DIA 独立分轨。先做粗剪验证故事和笑点，再做调色、音量与转场，不先打磨单个镜头。

### Gate 7 — 成片验收
至少进行三种检查：
- **叙事检查**：关掉声音看一遍，重要因果是否仍然可懂；只听声音，是否有台词与音效冲突。
- **连续性检查**：逐切检查方向、位置、道具、光线、服装与音画同步；检查角色漂移和中文乱码。
- **技术检查**：实际解码时长、帧数、冻结帧、对白峰值、混音峰值、字幕时间与画面范围。

通过后才标记为 release。未通过的版本要记录根因，而不是只写“感觉不对”。

## 4. 剧本设计的硬规则

1. 每集只有一个主目标、一个主要障碍、一条核心笑点机制和一个情感落点。
2. 笑点必须能用画面说明；台词负责快速补刀，不负责讲解笑点。
3. 连续镜头必须共享明确的空间与动作关系：谁在画面哪边、看向哪里、手里拿什么、动作从哪开始到哪结束。
4. 新出场角色、复杂多人构图、镜子、中文屏幕、手部精细操作都是高风险项，能删则删，必须保留则单独测试。
5. 不允许为了凑时长加“有质感但没有叙事作用”的空镜。
6. 一场戏可以留白，但留白必须有目的：让观众理解、等待反应或感受情绪，不是填补镜头时长。
7. 一次修复只改变一个变量。连续失败三次，应重新设计镜头，而不是继续叠加提示词。
8. 当前风格与角色状态如果仍未完全锁定，文档必须诚实标注暂定，不可在不同镜头中分别尝试新风格。

## 5. 多 AI / Git 协作纪律

- 每个代理使用独立分支；不直接向 main 推送。
- 主剧本只有一个 canonical 文件。评审意见写到独立 review 文档或 Issue，不在多个副本上平行修改。
- 变更主剧本必须附：改了什么、为什么改、对镜头数量/时长/生成成本的影响。
- 每次评审只处理一个主题：故事因果、喜剧节奏、画面连续性、音画剪辑不能混成一个无边界大改。
- README、AGENTS、制作状态要在阶段结束后更新；历史实验保留，当前状态只留一份真源。

## 6. 每集复盘的最小模板

- 本集想实现什么？
- 哪三个验收指标通过了？
- 哪三个问题仍然存在？
- 每个问题从哪一环开始出现：故事 / 分镜 / 首帧 / 视频生成 / 配音 / 混音 / 剪辑？
- 该问题连续失败了几次？是否已经换过维度？
- 本轮新增了什么可复用资产或经过验证的规则？
- 是否批准发布？若不批准，下一轮唯一要改的变量是什么？

## 7. 推荐落地顺序

对当前 EP01：先评审故事草案 → 定稿后检查分镜 → 关键首帧 contact sheet → 试生成 1–3 个高风险镜头 → 批量生成 → 配音与粗剪 → 音画与技术验收。

不要同时改风格、重写全片、换角色和重构代码。先让一集的制作方法闭环，再把它固化为下一集的模板。
