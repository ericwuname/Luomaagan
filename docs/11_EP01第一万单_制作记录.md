# EP01《第一万单》· 制作记录

> 日期：2026-10-23 凌晨
> 成片：`release/骡马阿甘_EP01_第一万单.mp4` — **113.96s / 2735 帧**
> 用户反馈起点：「剧情镜头感觉事情没有说得很清楚，故事连贯性不够，细节不够，
> 我需要想象补充……不应该是我脑补剧情，而是你能把故事说清楚」

---

## 一、上一版为什么需要观众脑补

| 病因 | 具体 |
|---|---|
| **身份没建立** | 观众不知道他是外卖员。没有接单、没有手机、没有送到的完整过程 |
| **数字没分量** | 「第五单」观众无感——第五单是什么概念？ |
| **"一直在送"没形成** | 只拍了一两单，重复感不够 |
| **中间跳跃没交代** | 9997 之后直接到最后一单，观众不知道中间发生了什么 |
| **因果缺失** | 他为什么一个人？为什么最后是陌生人给了他一块蛋糕？ |

---

## 二、这一版的四条解法

### ① 手机屏幕直接给信息（4 个程序渲染镜头）

**AI 生成中文必然乱码，这四镜一旦糊掉，故事就断了。所以用 PIL 画。**

| 镜头 | 内容 | 作用 |
|---|---|---|
| S01 | 「今日已送达 **9996** 单」 | **第一眼就知道：他是骑手，第一万单在即** |
| S04 | 「第 **9997** 单」（通知滑入） | 仪式感开始 |
| S11 | 「第 **10000** 单」 | 里程碑 |

**这比任何旁白都有效——观众自己看懂了。**

### ② 「还差三单」——把省略的部分交代掉

9997 之后，中间三单没有拍。所以加了一句台词：

> 阿甘（低头，轻声）：「还差三单。」

**9997 + 3 = 10000，观众自己就算得通。宁可说一句，也不要让观众自己补。**

### ③ 结构改成「他一直在门外」

原计划拍"三次门开"（蛋糕/玩具/小女孩），但生图一直卡住。
**换成更好的递进：**

```
09 门关上（他送完，被关在门外）
10 隔着窗看别人过生日（他在窗外，冷色，里面暖色）
13 门终于为他开了（小女孩仰头看他）
```

**这个递进比"三次门开"更准**——他不是被欢迎的人，他是送东西的人。
**门为他开的那一次，分量才够。**

### ④ 三次"别人的日子"

| 镜头 | 内容 | 台词 |
|---|---|---|
| 06 蛋糕店 | 接过系红丝带的蛋糕盒 | 店员：「小心点，生日蛋糕。」 |
| 10 隔窗 | 一家人围着蛋糕唱歌 | 无（留白） |
| 13 开门 | 小女孩的生日派对 | 小女孩：「叔叔，你也有蛋糕吗？」 |

## 六、踩到的坑

### 6.1 生图慢的原因不是参考图大小

为提速把参考图从 3MB 缩到 109KB，**速度没变**。
说明慢在 API 队列本身，不在上传体积。

### 6.2 某个镜头会反复卡住

`S07（门开+一家人+小孩）` 连续卡两次，每次 5 分钟以上无输出。
换成动物拟人（羊）也不行。**判断是这类构图的生成成功率高不起来。**

→ **应对：不要死磕单个镜头，换等价的叙事结构**
（"三次门开" → "他一直在门外"，反而更好）。

### 6.3 中文引号嵌在字符串里会炸

`"（第一次出现"生日"）"` → SyntaxError。
Python 源码里的注释/字符串**不能用中文引号包裹在双引号字符串内**。

## 七、还差什么（如实）

| 项 | 说明 |
|---|---|
| **没有 BGM** | 只有环境噪。**这是最大的欠缺** |
| 人类配角没统一成动物 | 面包师、保安是人的形象（世界观略乱） |
| 只有 1 个新镜头 | 三单只拍了 1 单（蛋糕店），"重复感"靠"门外三连"补 |
| 配额没用完 | 820 秒里只用了 7 秒（其余全复用），**还能做更完整的版本** |
